## 1. Что видит пользователь (Telegram-бот)

### 1.1. Старт
```
Привет! Я показываю историю квартиры по ссылке на объявление.

Пришли ссылку с Kufar, Realt, Onliner или Domovita, и я расскажу:
• сколько квартира реально продаётся
• как менялась цена
• есть ли она на других площадках дешевле
• стоит ли торговаться

/watch — следить за квартирой   /list — мои квартиры
```

### 1.2. Отчёт `/check` (главный экран продукта)
```
🏠 2-комн., 54 м², 5/9 эт., ул. Притыцкого, Фрунзенский р-н
Сейчас: $92 500 ($1 713/м²) — Kufar, агентство

⏳ На рынке: 94 дня (впервые замечена 20 июля на Realt)
   ↻ Перевыкладывалась 2 раза

   20.07  $98 000  Realt
   28.08  $95 000  Realt
   03.10  $92 500  Kufar (новое объявление, тот же объект)

🔁 Сейчас на других площадках:
   Onliner — $91 000 (другое агентство)  ← дешевле на $1 500

📊 Микрорайон: медиана $1 820/м² → эта квартира на 6% ниже медианы

💬 Вывод: висит 3 месяца, трижды снижалась, на Onliner дешевле.
   Торг реален. Начните с $88 000–89 000 и сошлитесь на цену на Onliner.

Уверенность склейки: высокая (адрес + площадь + 4 совпавших фото)
```

Если данных мало, бот прямо об этом пишет:
```

Нажмите «Следить» — сообщу, если цена изменится или объявление снимут.
[👁 Следить]
```

## 2. Архитектура

```
 ┌───────────── Источники ──────────────┐
 │  Kufar    Realt    Onliner  Domovita │
 └────┬────────┬────────┬────────┬──────┘
      │  адаптеры (1 файл на площадку)
      ▼
 ┌──────────────┐  раз в 30–60 мин, с паузами
 │  Collector   │──► raw → нормализация (USD, площадь, адрес)
 └──────┬───────┘
        ▼
 ┌──────────────┐      ┌──────────────┐
 │  PostgreSQL  │◄────►│   Matcher    │ склейка объектов, перевыкладывания,
 │ listings     │      │              │ дубли между площадками, хеши фото
 │ snapshots    │      └──────────────┘
 │ objects      │      ┌──────────────┐
 │ events       │◄────►│  Analytics   │ медианы районов, срок экспозиции,
 │ users/watch  │      │              │ индекс торга, отчёт /check
 └──────┬───────┘      └──────────────┘
        ▼
 ┌──────────────┐      ┌──────────────┐
 │ Telegram-бот │      │ Health/алерты│ «0 объявлений за сутки», ошибки парсинга
 └──────────────┘      └──────────────┘
```

**Стек:**
- Python 3.12, httpx, selectolax (если нужен HTML), Pydantic.
- SQLAlchemy 2 и Alembic, PostgreSQL (в разработке SQLite).
- aiogram 3, APScheduler.
- imagehash и Pillow для хешей фото.
- pytest.
- VPS за $5–10, Docker Compose.

### 2.1. Структура репозитория (план)
```
src/minsk_realty/
  sources/        # адаптеры: kufar.py, realt.py, onliner.py, domovita.py + base.py
  collector/      # планировщик, нормализация, запись снимков
  matching/       # отпечатки, phash, склейка, события
  analytics/      # медианы, экспозиция, индекс торга, сборка отчёта
  bot/            # aiogram: хендлеры, шаблоны сообщений
  db/             # модели, миграции
  health/         # мониторинг источников
tests/
  fixtures/<source>/   # сохранённые ответы площадок (без телефонов и имён!)
docs/
.claude/skills/minsk-realty/   # правила проекта для Claude
.claude/agents/                # 5 агентов команды
```

### 2.2. Модель данных
| Таблица | Ключевые поля | Зачем |
|---|---|---|
| `listings` | source, external_id, url, object_id, seller_type, first_seen, last_seen, status, posted_at_source | Одно объявление на одной площадке |
| `snapshots` | listing_id, seen_at, price_amount, price_currency, price_usd, fx_rate, area, rooms, floor, floors_total, address_raw, desc_hash | Каждый замер. Из них строится история |
| `photo_hashes` | listing_id, phash | Для склейки. Самих фото нет |
| `objects` | fingerprint, street_norm, house, rooms, area, floor, floors_total, district, microdistrict, lat, lon | Физическая квартира |
| `events` | object_id, type (`new`, `price_drop`, `price_up`, `relisted`, `cross_listed`, `removed`, `returned`), payload, at | Лента для отчёта и уведомлений |
| `users`, `watchlist`, `checks` | — | Пользователи, их подписки и запросы |

## 3. Команда агентов

Каждый агент — это файл в `.claude/agents/`, у каждого своя зона ответственности. Общие правила проекта лежат в скилле `.claude/skills/minsk-realty/SKILL.md`, его читают все агенты.

| Агент | Имя | Зона ответственности | Не трогает |
|---|---|---|---|
| `stas-scraper` | **Стас**, сборщик | Адаптеры площадок, разведка эндпоинтов, частота опроса, нормализация сырых данных, фикстуры | Логику склейки, бота |
| `vera-matcher` | **Вера**, склейка | Отпечатки объектов, phash, перевыкладывания, дубли между площадками, генерация событий | Сетевые запросы к площадкам |
| `lev-analyst` | **Лев**, аналитик | Медианы по районам, срок экспозиции, индекс торга, текст отчёта `/check`, еженедельная сводка, критерии из раздела 9 идеи | Сбор данных, Telegram API |
| `mila-bot` | **Мила**, бот и UX | aiogram-бот, команды, тексты сообщений, разбор ссылок, список отслеживаемых квартир, оплата (позже) | Расчёты аналитики (вызывает функции Льва) |
| `gleb-guard` | **Глеб**, контроль | Ревью кода, тесты, проверка на персональные данные, здоровье источников, бережность к площадкам, миграции, деплой | Новые фичи |

**Как они работают вместе:**
```
Стас (сбор) → Вера (склейка + события) → Лев (выводы) → Мила (показ пользователю)
                         ↑ Глеб проверяет каждый шаг ↑
```

**Примеры задач:**
- «Добавь Onliner» → Стас (адаптер + фикстуры) → Вера (проверить склейку с Kufar/Realt) → Глеб (ревью, проверка на персональные данные).
- «Почему отчёт показал не ту квартиру?» → Вера (разбор склейки) → Глеб (регрессионный тест).
- «Сделай еженедельную сводку» → Лев (расчёт + текст) → Мила (публикация в канал).

## 4. Этапы в виде задач для агентов

| # | Задача | Агент | Готово, когда… |
|---|---|---|---|
| 1 | Разведка эндпоинтов Kufar и Realt, сохранение фикстур | Стас | Есть рабочий запрос, фикстура и список полей (дата публикации? тип продавца?) |
| 2 | Схема БД и миграции | Глеб + Стас | `alembic upgrade head` проходит |
| 3 | Сборщик Kufar и Realt + планировщик | Стас | Сутки работы, снимки в БД, алерт срабатывает при поломке |
| 4 | Склейка уровня 1 (отпечаток) + события | Вера | Тесты на перевыкладывание и снижение цены проходят |
| 5 | Склейка уровня 2 (phash) + дубли между площадками | Вера | Тест «одна квартира на Kufar и Realt = один объект» |
| 6 | Бот: `/check`, `/watch`, `/list` | Мила + Лев | Отчёт по живой ссылке приходит меньше чем за 3 секунды |
| 7 | Onliner и Domovita | Стас → Вера | Объекты склеиваются по 4 площадкам |
| 8 | Метрики для проверки гипотезы (неделя 6) | Лев | Отчёт: доля перевыкладываний, дублей, снижений |
