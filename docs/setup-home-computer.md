# Запуск на домашнем компьютере

Сборщик должен работать с белорусского интернета: Kufar не отвечает на запросы из-за рубежа. Домашний компьютер в Минске подходит, если он почти всегда включён.

**Что нужно:** Windows 10/11, macOS или Linux, от 4 ГБ памяти, ~10 ГБ свободного места, постоянный интернет.

---

## Шаг 1. Отключить сон

Сборщик ходит на площадки раз в 30–60 минут. Если компьютер засыпает, история рвётся.

- **Windows:** Параметры → Система → Питание → «Переводить в спящий режим» → **Никогда** (при питании от сети).
- **macOS:** Настройки → Аккумулятор/Энергосбережение → «Предотвращать автоматический переход в режим сна».
- **Linux:** отключить suspend в настройках питания.

Выключать монитор можно, это не мешает.

## Шаг 2. Установить Docker и Git

- **Windows / macOS:** [Docker Desktop](https://www.docker.com/products/docker-desktop/). При установке на Windows согласиться на WSL 2. В настройках Docker Desktop включить **Start Docker Desktop when you sign in**.
- **Linux:** Docker Engine и плагин compose по инструкции для вашего дистрибутива.
- **Git:** [git-scm.com](https://git-scm.com/downloads). Можно обойтись без него: скачать архив ветки на GitHub (Code → Download ZIP).

Проверка в терминале (на Windows — PowerShell):
```
docker --version
docker compose version
```

## Шаг 3. Скачать проект

```
git clone https://github.com/carrionbusiness07-dev/-.git minsk-realty
cd minsk-realty
git checkout claude/minsk-realty-concept
```

## Шаг 4. Создать Telegram-бота

1. В Telegram откройте **@BotFather** → `/newbot` → задайте имя → получите **токен** вида `1234567:AA...`.
2. Напишите своему боту любое сообщение.
3. Откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id":123456789` — это ваш **ADMIN_CHAT_ID**.
   Если бот уже запущен (`docker compose up -d`), он сам забирает сообщения, и эта страница покажет ошибку или пустой список. Тогда сначала выполните `docker compose stop bot`, а после — `docker compose start bot`.

Токен — это пароль от бота. Не публикуйте его и не коммитьте.

## Шаг 5. Заполнить `.env`

Скопируйте образец:
- Windows: `copy .env.example .env`
- macOS/Linux: `cp .env.example .env`

Откройте `.env` в блокноте и заполните:

| Поле | Что вписать |
|---|---|
| `POSTGRES_PASSWORD` | длинный случайный пароль |
| `SELLER_KEY_SALT` | длинная случайная строка. **Задаётся один раз и больше никогда не меняется** |
| `TELEGRAM_BOT_TOKEN` | токен из шага 4 |
| `ADMIN_CHAT_ID` | id из шага 4 |
| `CHANNEL_ID` | необязательно: канал для недельной сводки, см. шаг 9 |

Сгенерировать случайные строки:
- PowerShell: `-join ((48..57)+(97..122) | Get-Random -Count 48 | % {[char]$_})`
- macOS/Linux: `openssl rand -hex 32`

Сохраните копию `.env` в надёжном месте, например в менеджере паролей. Без `SELLER_KEY_SALT` старые данные не свяжутся с новыми.

## Шаг 6. Снять первые живые ответы площадок

Это нужно, чтобы закрыть неизвестные поля Kufar: этаж, валюту, формат адреса.

```
docker compose build
docker compose run --rm --user root -v "${PWD}/tests/fixtures:/app/tests/fixtures" collector python scripts/capture_fixture.py kufar
docker compose run --rm --user root -v "${PWD}/tests/fixtures:/app/tests/fixtures" collector python scripts/capture_fixture.py realt
```

(На macOS/Linux вместо `${PWD}` можно писать `$PWD`.)

В `tests/fixtures/kufar/` и `tests/fixtures/realt/` появятся файлы с сегодняшней датой. Скрипт уже вырезал из них телефоны и имена. **Пришлите эти файлы в чат** вместе с тем, что скрипт напечатал в терминал. Grant проверит их, и мы уберём пометки UNVERIFIED в адаптерах.

Если Kufar ответил `403` или «Доступ ограничен», напишите об этом. Значит, ваш провайдер выходит в интернет не через белорусский адрес, и надо разбираться отдельно.

## Шаг 7. Запустить сбор

```
docker compose up -d
docker compose logs -f collector
```

В логе должны появиться строки вида `kufar: просмотрено N, ошибок 0, полный проход: True`. Выйти из просмотра логов: `Ctrl+C`, сборщик продолжит работать.

Дальше всё работает само:
- после перезагрузки компьютера Docker Desktop стартует и поднимает сборщик (`restart: unless-stopped`);
- если с площадкой что-то не так, бот пришлёт вам алерт, но не чаще раза в сутки на одну проблему.

## Шаг 8. Открыть кабинет «Хроника»

`docker compose up -d` поднимает и кабинет. Откройте в браузере **http://localhost:8080**.

- **Сводка**: что изменилось за сутки или неделю (подешевели, перевыложены, сняты, новые) и пульс рынка.
- **Объекты**: все квартиры в продаже, сортировка по сроку на рынке, снижениям, цене.
- **Карточка квартиры**: хроника цены, где ещё продаётся, вывод о цене. Сюда же ведёт поле «Ссылка Kufar или Realt».
- **Рынок** и **Источники**: медианы по районам и здоровье сборщика.

Кабинет открывается только с этого компьютера. Пока сборщик не набрал данных, страницы почти пустые: первые цифры появятся через пару проходов, а история — через несколько недель.

## Шаг 9. Telegram-бот для покупателей

Бот из шага 4 работает и для алертов, и для пользователей: второй токен не нужен. `docker compose up -d` запускает его вместе со сборщиком (сервис `bot`). Если `TELEGRAM_BOT_TOKEN` не задан или Telegram его не принял, сервис `bot` один раз пишет об этом в лог («TELEGRAM_BOT_TOKEN не задан…») и ждёт, ничего не делая: в цикле он не перезапускается, сборщик и кабинет работают как обычно. Когда впишете токен в `.env`, выполните `docker compose up -d --force-recreate bot`.

Проверить, что бот запустился:
```
docker compose logs --tail 20 bot
```
В логе должна быть строка `Run polling for bot @имя_вашего_бота`. Если вместо неё «Telegram не принял TELEGRAM_BOT_TOKEN», проверьте токен в `.env`.

Бот увидят чужие люди, поэтому у **@BotFather** стоит поправить имя (`/setname`), описание (`/setdescription`) и аватар (`/setuserpic`). Команды в меню бот выставит сам.

**Что видит пользователь:**
- `/start` — что умеет бот и какие площадки он понимает: Kufar, Realt, Onliner и Domovita.
- Ссылка на объявление (можно просто переслать текст со ссылкой) — отчёт: сколько квартира на самом деле продаётся, история цены, другие площадки, сравнение с медианой и вывод о цене. Под отчётом кнопки «Следить» и «Открыть объявление».
- Если объявления ещё нет в базе, бот так и пишет: сборщик обходит площадки раз в 30–60 минут.
- «Следить» добавляет квартиру в `/list` (до 10 квартир, меняется через `BOT_WATCH_LIMIT`). Бот пишет, если квартира подешевела или подорожала, её перевыложили, сняли или она вернулась. По одной квартире не чаще раза в час, несколько новостей приходят одним сообщением.
- `/forget` удаляет всё, что бот знает о пользователе: Telegram ID, список и историю проверок.

Бот хранит только Telegram ID пользователя: ни имени, ни username. Телефоны продавцов он не показывает.

**Недельная сводка в канал (необязательно):**
1. Создайте канал в Telegram и добавьте бота в администраторы с правом публиковать сообщения.
2. Впишите в `.env` `CHANNEL_ID=@имя_канала` (для закрытого канала нужен числовой id вида `-100…`).
3. `docker compose up -d`.

Сводка за прошлую неделю выходит в понедельник в 10:00 по Минску. Если компьютер в это время был выключен, бот опубликует её позже, но не позднее среды. В личном чате с ботом (если `ADMIN_CHAT_ID` — ваш личный id, а не группа) можно посмотреть сводку командой `/weekly` и опубликовать её вручную командой `/weekly publish`. Если бот остановился посреди публикации, он после запуска напишет вам, что нужно проверить канал.

## Шаг 10. Сторож: узнать, что компьютер или сборщик выключился

Алерты в Telegram отправляет сам этот компьютер. Если пропал свет или интернет, закрылся Docker или Windows ушёл в перезагрузку, отправлять их некому. Сторож работает наоборот: сборщик после каждого цикла шлёт ему пустой сигнал «я жив», и если сигнала нет 2 часа, сторож сам пишет вам. Наружу уходит только этот сигнал, никаких данных.

1. Откройте **https://healthchecks.io** → **Sign Up** → зарегистрируйтесь по e-mail. Бесплатного тарифа хватает.
2. Нажмите **Add Check**. Name: `Хроника — сборщик`. В **Schedule** поставьте **Period: 1 hour** и **Grace Time: 1 hour** → **Save**.
3. Скопируйте **Ping URL** вида `https://hc-ping.com/…`. Это ключ проверки: не показывайте его на скриншотах.
4. Куда присылать тревогу: письма на e-mail включены сразу. Чтобы получать сообщения в Telegram, откройте **Integrations** → **Telegram** → **Add Integration** и следуйте подсказкам (бот healthchecks попросит нажать /start).
5. Добавьте адрес в `.env`:
   ```
   cd D:\minsk-realty
   notepad .env
   ```
   В конец файла допишите строку `HEALTHCHECK_URL=https://hc-ping.com/…` (ваш адрес), сохраните и закройте Блокнот.
6. Примените: `docker compose up -d`. Через 10–20 минут, когда сборщик закончит первый цикл, проверка на сайте станет зелёной (**up**).

Если в цикле не удалась ни одна площадка, сборщик сразу шлёт сигнал «сбой», и сторож сообщит об этом, не дожидаясь двух часов.

Чтобы компьютер не перезагружался сам: Параметры → Центр обновления Windows → Дополнительные параметры → **Период активности** → «Вручную», 8:00–2:00. Ночную перезагрузку после обновления сторож заметит и сообщит.

## Полезные команды

| Что | Команда |
|---|---|
| Статус | `docker compose ps` |
| Логи кабинета | `docker compose logs --tail 100 web` |
| Логи бота | `docker compose logs --tail 100 bot` |
| Последние логи | `docker compose logs --tail 100 collector` |
| Остановить | `docker compose stop` |
| Запустить снова | `docker compose up -d` |
| Обновить код | `git pull` → `docker compose up -d --build` |
| Снять остановку площадки после 403/429 | `docker compose run --rm collector python -m minsk_realty.collector --once --unblock kufar` |
| Логи бэкапа | `docker compose logs --tail 20 backup` |

## Резервные копии

Сервис `backup` раз в сутки сам кладёт копию базы в папку `backups` внутри проекта (например, `D:\minsk-realty\backups\realty-2026-10-24.dump`). Хранятся последние 14 дней. Если компьютер ночью выключен, копия появится через час после включения.

Накопленную историю ничем не заменить, поэтому раз в неделю копируйте свежий файл из `backups` за пределы компьютера, лучше всего на флешку. В копии есть Telegram ID пользователей бота, а это персональные данные. Поэтому в облако или в почту кладите только архив с паролем (7-Zip → «Добавить к архиву» → задать пароль и шифрование AES-256). Старые копии удаляйте так же, как бэкапы в разделе про `/forget`: храните не дольше 4–8 недель.

**Восстановить базу из копии** (например, после переустановки):
```
docker compose stop collector web bot
docker compose exec backup pg_restore --clean --if-exists -d realty /backups/realty-2026-10-24.dump
docker compose up -d
```
Вместо даты подставьте имя нужного файла из папки `backups`.

Если пользователь удалил свои данные командой `/forget`, его Telegram ID исчезает из базы, но остаётся в старых бэкапах, пока вы их не удалите. Не храните бэкапы дольше, чем нужно: например, только последние 4–8 недель.

## Что важно знать

- Сборщик бережный: одна площадка, один запрос за раз, паузы между страницами, проход раз в 30–60 минут.
- Если площадка всё же ограничит доступ, ограничение коснётся вашего домашнего IP: вы можете временно не открывать её в браузере. Поэтому сборщик после трёх отказов подряд сам останавливается.
- Порты наружу не открываются: база доступна только внутри Docker.

## Разовая пересклейка Kufar после обновления 23.10.2026

До этого обновления сборщик не видел адрес в объявлениях Kufar, и они склеивались с Realt хуже. После обновления адрес пишется, но уже собранные объявления нужно один раз пересклеить:

1. Обновите код: `git pull`, затем `docker compose up -d --build`.
2. Подождите полного прохода Kufar на новом коде: на странице **Источники** у Kufar появится строка «успешно · Полный: да» с временем **после** обновления (обычно до часа).
3. Остановите сборщик и бота, пересклейте, запустите снова:
   ```
   docker compose stop collector bot
   docker compose run --rm collector python -m minsk_realty.matching relink-unaddressed
   docker compose up -d
   ```
   Команда напишет, сколько объявлений пересклеено. Повторный запуск ничего не сломает: уже пересклеенные объявления он не трогает.
